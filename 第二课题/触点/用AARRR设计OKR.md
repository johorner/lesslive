## 定义
用 AARRR 的五个阶段作为永续的目标（O），将用户旅程、增长策略和目标管理融合在一个看板中，大幅降低个人的精力消耗。
## 适用场景
- 一个人单打独斗的雨燕族
- 既要设计用户旅程，还要负责增长策略（AARRR），又要管理阶段目标（OKR）
- 追求最小化和高效能，精力用在业务推进而非工具管理

## 核心洞察
### 传统方式的问题
**管理工具分离：**
- AARRR 管理增长（获取、激活、留存、收入、推荐）
- OKR 管理目标（设计 O、分解 KR）
- 需要在两个工具/看板间切换

**设计 OKR 的负担：**
- 每个周期都要重新设计 O（目标是什么）
- 设计一条漂亮的 OKR 是重技术活
- 耗费大量精力在"想目标"而非"做事情"

### LessLive 的解决方案
**五个永续的 O：**
AARRR 的五个阶段本身就是五个标准的目标（O）：
1. **Acquisition（获取）** - 我要获取用户
2. **Activation（激活）** - 我要激活用户
3. **Retention（留存）** - 我要留存用户
4. **Revenue（收入）** - 我要实现收入
5. **Referral（推荐）** - 我要用户推荐

**关键转变：**
- 从"设计 OKR"变成"填充行动"
- 从"创造目标"变成"执行标准目标"
- 五个目标永远存在，不需要反复思考

### 重新定义 OKR
**传统 OKR =  我要去哪儿，以及如何证明我到了那儿（只是证明）**

```
O：建立初始认知
  KR1：发布 10 篇内容（任务）
  KR2：获得 200 下载（数字）
```

问题：只有任务和数字，不知道"为什么这样做"、"如何做到"

**LessLive-OKR 的 KR = 我如何去到那儿 + 如何证明我到了那儿**

```
O：建立初始认知（我要去哪儿）

Acquisition（获取策略）：
  KR1：通过对比类内容在小红书获取 700 曝光
       ↑策略         ↑渠道    ↑证明

Activation（激活策略）：
  KR2：优化 GitHub 下载体验获得 200 下载
       ↑策略                ↑证明
```

**KR 的三个要素：**
1. **策略**（如何去）：对比类内容、优化体验
2. **渠道**（在哪去）：小红书、GitHub
3. **证明**（到了没）：700 曝光、200 下载

提示：如何到那儿和如何证明到了可以分别设计成独立的 KR

## 看板结构
### 看板名
根据当前所处阶段，设计一个激励人心的目标，作为最大的 O，提供方向或激励：
**示例 1：时间周期型**

```
O：2026-Q4 旅程
```

**示例 2：目标型**

```
O：建立初始认知
```

**示例 3：激励型**

```
O：今年春节过个好年
```

### 列（List）
AARRR 五个阶段，首先是看板总 O 的五个 KR，同时作为内部的五个永续 O：
- **Acquisition（获取）** - 如何让用户发现我
- **Activation（激活）** - 如何让用户采取行动
- **Retention（留存）** - 如何让用户持续使用
- **Revenue（收入）** - 如何让用户付费
- **Referral（推荐）** - 如何让用户推荐

### 卡片（Card）
每张卡片是该列的一个具体的 KR，包含策略、行动和证明。
**卡片命名原则：**
战役级行动，不是琐碎任务。
**✅ 好的卡片示例：**

```
通过对比类内容在小红书获取 700 曝光
通过深度案例在少数派获取 200 曝光
优化 GitHub 下载体验获得 200 下载
设计视频号挂车路径实现 10 个付费用户
```

**❌ 不好的卡片示例：**

```
写一篇文章（太琐碎，没有策略）
改 README（太具体，没有目标）
发小红书（没有策略和证明）
```

**卡片内容结构：**

```
卡片标题：通过[[对比类内容]]在小红书获取 700 曝光

卡片创建的文档：
- 策略：对比类内容（LessLive vs 第二大脑、vs P.A.R.A.）
- 渠道：小红书、少数派
- 目标：700 曝光
- 状态：☑ 进行中
- 时间：📅 2026-10-25
- 链接：[[LessLive/故事/对比类内容]] # 该内容单元下可以有多个具体的内容文档
```

### 复选框状态
- 未开始 `- [   ]`
- 进行中 `- [ / ]
- 已完成 `- [ x ]`

**优先级管理：**
- 将紧急重要的拖到 list 列表顶部（Doing）
- 将已完成的拖到 list 列表底部（Done）
- 中间的是待办（Todo）
- 不需要精细的边界，一眼就知道

### 时间标签
给卡片添加时间标签（在卡片上输入 `空格+@` 激活时间输入）：

```
📅 2026-11-15（截止日期）
📅 进行中（持续任务）
📅 每周二（定期任务）
```

看板即可变身日程表。

## 使用流程
### 初始设置
**1. 创建看板**
- 看板名：选择时间周期或目标
- 创建五个列：Acquisition、Activation、Retention、Revenue、Referral

**2. 设为 HomePage**
- 打开即全局视野
- 一眼看到所有工作领域
- 一眼看到当前进度

### 日常操作
**1. 新增 KR**
- 在对应的策略列（O）下创建卡片
- 卡片命名：策略 + 渠道 + 证明
- 示例：在 Acquisition 下创建"通过对比类内容在小红书获取 700 曝光"

**2. 卡片详情**
- 点击卡片进入详情
- 记录：策略、渠道、目标、时间
- 添加双链：链接到具体执行文档
- 示例：[[反对第二大脑]]

**3. 调整优先级**
- 上下拖动卡片改变顺序
- 紧急的置顶，完成的沉底
- 不需要复杂打分

**4. 更新进度**
- 为卡片内容创建文档
- 勾选复选框
- 移动它们到正确的位置

### 阶段性维护
**周回顾：**
- 查看每个列的进度
- 调整优先级和时间
- 补充新的 KR

**季度归档：**
- 将已完成的卡片归档
- 将不再需要的卡片删除
- 保持看板简洁

## 设计原则

基于 LessLive 最小化原则：
### 低成本
- 一个看板搞定两个管理需求（AARRR + OKR）
- 不需要多个工具切换
- 不需要复杂的 OKR 设计技术

### 少依赖
- 不依赖团队协作功能
- 不依赖复杂的打分和评估系统
- 简单、直观、够用

### 高效能
- 精力用在外部开疆拓土（业务推进）
- 而不是内部管理消耗（工具维护）
- 工具是为了生存，不是为了秀肌肉

---

## 价值与效果
### 消灭技术内耗
**不需要反复设计 O：**
- 五个永续的 O 已经确定
- 不需要每个周期重新思考"目标是什么"

**不需要在多个工具间切换：**
- 一个看板管理用户旅程和任务目标
- 增长策略和执行进度一目了然

### 策略清晰完整
**AARRR 提供策略维度：**
- 每个 KR 都有明确的策略归属
- 知道"为什么这样做"
- 覆盖用户完整生命周期，不遗漏关键环节

**KR 包含完整路径：**
- 不只是"要达到什么"（指标）
- 还知道"如何达到"（策略）

### 降低认知负担
**从创造到填充：**
- 不需要创造目标（O 已经是目标）
- 只需要填充行动（KR）

**一眼看到全局：**
- 五个策略维度清晰展示
- 当前进度一目了然
- 优先级清晰可见

### 适合个人日常生活
**一个人全包的场景：**
- 需要清晰的策略指引
- 不能靠团队讨论明确方向
- AARRR 提供现成的策略框架

**简单、直观、够用：**
- 不需要复杂的团队协作功能
- 不需要高大上的管理系统
- 够用就好

## 示例
### 真实案例：LessLive 首发阶段

这是 LessLive 设计者的真实 OKR 看板（2024-10-25 开始）

**看板名：**

```
O：[[拿到首发基准数据]]
```

**时间周期：**
- 做完为止（不设死线）
- 检查点：每周五

---

**Acquisition（拉新）：**

```
☐ 首发渠道策略
   设计：选择哪些渠道、如何整合
   链接：[[旅程/拿到首发基准数据/媒体渠道策略]]

☐ 推出雨燕宣言
   策略：用愿景和使命顶上去
   链接：[[第三课题/LessLive/故事/雨燕宣言]]

☐ 重构微信朋友圈
   策略：私域起点，精准触达
   链接：[[旅程/拿到首发基准数据/媒体渠道策略]]
```

---

**Activation（促活）：**

```
☐ 高反差高争议高共鸣内容策略
   策略：引发讨论，别死气沉沉
   链接：[[旅程/拿到首发基准数据/促活策略]]

☐ 反对第二大脑
   内容：高争议内容，引发讨论
   链接：[[第三课题/LessLive/故事/反对第二大脑]]

☐ 为什么没有收件箱
   内容：高反差内容，引发好奇
   链接：[[第三课题/LessLive/故事/为什么没有收件箱]]
```

---

**Revenue（转化）：**

```
☐ 免费开源包可下载
   转化目标：下载
   链接：[[第三课题/LessLive/产品/开源包]]

☐ 社群价值体系设计
   转化目标：进群
   链接：[[旅程/拿到首发基准数据/转化路径设计]]
```

---

**Retention（留存）：**

```
☐ 社群运营方案设计
   策略：如何让人留下来
   链接：[[第三课题/LessLive/社区/社群运营]]
```

---

**Referral（推荐）：**

```
☐ 攻略性高价值内容创作
   策略：让人愿意收藏和转发
   链接：[[第三课题/LessLive/故事/把 obsidian 仓库打造成人生操作系统]]
```

---

### 关键特点

**1. O 激励人心**
- "拿到首发基准参数"
- 不是"建立初始认知"
- 明确方向和目的

**2. 不拍脑袋定指标**
- 没有"700 曝光"、"200 下载"
- 首发阶段目标是拿数据，不是达到数字
- 没有可续依据的指标都是拍脑袋不负责的设计

**3. 战役级动作**
- 推出雨燕宣言（不是"写文章"）
- 反对第二大脑（不是"发小红书"）
- 高反差内容策略（不是"内容营销"）

**4. 首发阶段策略**
- 促活：高反差高争议高共鸣（引发讨论）
- 拉新：用愿景和使命顶上去（雨燕宣言）
- 转化：下载和进群（不追求付费）

**5. 卡片链接清晰**
- 策略类 → 旅程文件夹
- 内容类 → 第三课题
- 不在看板重复内容

## 传统 OKR Vs LessLive-OKR

| 维度         | 传统 OKR           | LessLive-OKR             |
| ---------- | ---------------- | ------------------------ |
| **O 的设计**  | 每个周期重新设计         | 五个永续 O，不需要设计             |
| **策略指引**   | 无（只有任务和数字）       | 有（AARRR 五个策略维度）          |
| **KR 的内容** | 证明指标（如何证明到了）     | 策略 + 行动 + 证明（如何去 + 证明到了） |
| **认知负担**   | 高（需要创造目标）        | 低（填充行动即可）                |
| **工具数量**   | 2 个（AARRR + OKR） | 1 个（融合看板）                |
| **完整性**    | 可能遗漏环节           | 覆盖完整生命周期                 |
| **适用场景**   | 团队协作             | 一个人单打独斗                  |
| **管理成本**   | 高（需要维护多个看板）      | 低（一个看板全局）                |

## 总结
### 核心价值
用 AARRR 的五个阶段作为永续的 O，将增长管理和目标管理融合在一个看板中，让 KR 包含"如何去"的策略和"证明到了"的指标，大幅降低雨燕族的精力内耗。
### 三个关键创新
1. **五个永续的 O**：不需要反复设计目标
2. **KR 包含策略**：不只是数字，还有如何达到的路径
3. **一个看板融合**：增长和目标管理合二为一

### 适用人群
一个人单打独斗的雨燕族，需要清晰的策略指引和简单高效的工具，把精力用在外部开疆拓土，而不是内部管理内耗。
