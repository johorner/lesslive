## 核心定义

基于 OKR 和 AARRR 方法，把内容策略、渠道策略、运营目标、计划管理、进度跟踪等相关运营工作融为一体。 
说明：本工具已将 AARRR 从狭义互联网用户模型做泛化，可适用于个人项目、自我成长、小团队业务。

---
## 核心机制

用一个看板同时呈现五个运营维度，不是分散管理，而是自然融合：

| **目标怎么定** | **O:Acquisition获取** | **O:Activation 活跃** | **O:Retention留存** | **O:Revenue转化** | **O:Referral推荐** |
| :-------: | :-----------------: | :-----------------: | :---------------: | :-------------: | :--------------: |
| **内容怎么发** |                     |                     |                   |                 |                  |
| **渠道怎么选** |                     |                     |                   |                 |                  |
| **计划怎么管** |                     |                     |                   |                 |                  |
| **进度怎么跟** |                     |                     |                   |                 |                  |

`不要填写表格，这是示例`
### 横向读
AARRR 五列 = 五个目标（O），每列表头就是一个运营目标
把他们作为永续 O，任何阶段都将围绕这五个目标展开运营，形成稳定运行框架。
### 纵向读
每列下的卡片可以同时回答内容策略、渠道策略、任务管理等相关问题
  - 用什么内容？→ 达成该列目标的内容策略（选题、活动、号召等）
  - 去哪里发布？→ 达成该列目标的渠道策略（线上、线下、平台、投流等）
  - 什么顺序做？→ 卡片的排列顺序就是计划（第一行卡片是最高优先级）
  - 做到哪了？→ 卡片的位置就是进度（上：进行中，中：待办，下：完成）

## 设计流程
### ① 解析蓝图
将脑海中关于蓝图实施的所有构想，按照 AARRR 结构创建卡片填入看板，**不怕卡片多，这是正常的**，重点是它们归属正确的列。
### ② 设计旅程
完整遍历 AARRR 所有环节，结合当前阶段实际情况，删除不必要的卡片，尚有价值的未完成卡片可以直接保留流转，剩余卡片就是当前阶段性旅程里程碑的任务。也可以先设计阶段性旅程目标，将其解析为看板。
### ③ 维护卡片
根据阶段性旅程总目标，对每张卡片进行精细化调整，确保卡片能精准表达**如何达成以及如何证明已经达成目标**。

---
## OKR设计
### 目标设计
- 目标是“要去哪里”，即达到的终点和目的地
- 直接将 AARRR 作为每阶段的具体运营目标
- 在其基础上提炼当前阶段总目标作为看板名
- 阶段目标应指明方向，激励人心、鼓舞士气

### 关键成果
- 如何去那里：达成目标的策略、手段以及方法
- 如何证明已经到达：设定达成目标的指标和参数

> [!ai]- AI 辅助
> - 协助用户解析蓝图时，鼓励穷尽所有可能性，不要过早筛选，让卡片先填满看板。
> - 在设计旅程阶段，帮助用户识别现实约束（时间、预算、资源），筛选出当前阶段必需的卡片。
> - 提醒用户：五列永续目标始终可见，即便某列当前不投入，也要思考是否需要前置准备。
> - 协助用户设计关键成果时，确保回答三个问题：去哪里（目标）、如何去（策略）、如何证明到达（指标）。
> - 尊重用户的取舍决策，框架只负责把选项和代价摊开，不替用户做判断。
> - 当用户项目处于不同阶段（新项目、进行中、转型），调整解析蓝图和设计旅程的侧重点。
