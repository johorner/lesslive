## 目标

明确自己想要得到的和愿意付出的，并为它们提供坚实的理论依据，为生活提供稳定且强劲的动力和方向。

---
## 结构

> [!multi-column] 
>
>> [!info]  [[愿景]]｜**由外向内的获取**
>> 1️⃣ 发自内心想要得到的对自己有利的成果
>> 2️⃣ 个人向往与憧憬的未来生活和人生状态
>> 
> 
>> [!info]  [[使命]]｜**由内向外的付出**
>>  1️⃣ 持续关注特定领域或对象的特定问题和现象
>>  2️⃣ 愿意付出并承担责任，因改善而创造的价值
> 
>> [!info]  [[主张]] ｜**愿景使命的理论**
>> 1️⃣ 沉淀立场清晰、逻辑完整、证据充分的论证过程和成果
>> 2️⃣ 为愿景和使命提供强有力的理论支撑，形成自己的信仰

---
## 说明

- 愿景只研究从外面拿回来的，自己想要的，不要研究用什么方法拿回来。
- 使命只陈述问题的客观现状以及希望改善后的样子，不要谈个人回报和具体方法。
- 除了进一步打磨和完善，新增任何内容时应谨慎对待，反复确认它是否应该出现在这里。
- 这是把自己的内在显性化的过程，不必写成完整漂亮的文档，把内在朦胧的向往、想法和认知变成自己看得见的文字，才有机会辨认：我真正想要的是什么，哪些是部分让期待。

```
设计示例：
愿景：我要成为一名心理咨询师、创办一家心理门诊。这是愿景，是自己的事，和他人无关，不提如何做到。
使命：我希望人们保持心理健康，不受情绪的折磨。这是使命，关乎他人利益。和自己是否能够实现无关。
主张：抑郁只是情绪感冒罢了……。是支撑使命和愿景的观点，让愿景和使命更加坚定。
```

## 规则
### 不可迁移，只被引用
- 内驱力是系统的能源中心，是基础设施
- 一旦进入内驱力（愿景、使命、主张），就是永久归属
- 其他模块消费时，通过引用或二创，不是迁移

### 内驱力保持自身干净
- 不假设应用场景：不为对外发布而写，不为业务需求而写
- 核心原则：逻辑完善、证据充分、立场鲜明
- 性质：这是"我的信仰体系"，不是"营销素材"
### 这样设计的好处
1. 职责清晰

内驱力：纯粹的信仰和方向（不管怎么用）
第二课题：基于内驱力设计业务策略（怎么做）
第三课题：引用内驱力创作对外内容（怎么说）
2. 解耦彻底

- 内驱力的内容调整，不影响其他模块（只要引用还在）
- 第三课题的表达方式调整，不影响内驱力的纯净性

3. 维护成本低

- 内驱力：高内聚在一处，单一真相源
- 消费模块：引用 + 二创，各自维护各自的表达
### 具体应用示例

```
示例 1：主张的使用

内驱力/主张/明白的事比赚到的钱重要.md
（纯粹的理论论证，不考虑对外发布）

## 观点
成长比成功重要，明白的事比赚到的钱重要

## 论证
- 成功是外部评价...
- 成长是内在获得...

## 证据
- ...

第三课题/LessLive/故事/为什么选择 LessLive.md
（针对 LessLive 用户的对外表达）

基于[[主张/明白的事比赚到的钱重要]]，我设计了 LessLive...

（二创：用受众听得懂的语言，加上场景化案例）

示例 2：愿景的使用

内驱力/愿景/想要成为这样的人.md
（纯粹的自我期望，不加修饰）

- 有意识的执行者，不被焦虑劫持
- 能接受"足够好"，不追求病态完美
- ...

第二课题/蓝图/服务设计商业化.md
（基于愿景设计业务策略）

基于我想成为[[愿景/想要成为这样的人]]，
我需要设计一个低依赖、可持续的商业模式...
```

> [!ai]- AI 辅助
> - 通过提问协助用户辨明真实意愿和愿意承担的责任，不用社会期待替用户设定愿景与使命。
> - 严格区分愿景、使命和主张，发现内容越界时指出；不把实现方法写进愿景，也不把个人回报写进使命。
> - 协助论证内驱力的整体逻辑，检验愿景与使命之间的关联；区分事实、判断、假设和证据，主动提出反例与疑点，避免只搜集支持材料。
> - 不迎合或默认赞同用户；发现矛盾、依据不足或不确定之处时明确说明，并给出讨论与修订建议。
> - 内驱力内容由用户决定和确认；不把它改写成对外宣传文案，具体场景表达由第三课题处理。
